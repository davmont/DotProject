Two framework facts that shape the severities (verified, not assumed):

* Core `index.php:244-247` `require`s `modules/<m>/<dosql>.php` BEFORE any module permission check, and the core never redirects on `!$canAccess` (each module's own file does). So a dosql file without its own `getPermission()`/`canEdit` check is reachable by **any logged-in user, even one with no access to that module**. `CDpObject::store()` (classes/dp.class.php:213) has **no ACL check**; `CDpObject::delete()`/`canDelete()` (dp.class.php:249-333) do check `checkModuleItem(...,'delete')`, but several modules override `delete()` without that check.
* `$AppUI->___()` / `dPformSafe()` default to `htmlentities(..., ENT_COMPAT)` (classes/ui.class.php:499-500) so a single quote `'` is NOT encoded; and `dPformSafe($x, DP_FORM_URI)` only does `str_replace(' ', '%20')` (ui.class.php:496) with **no HTML escaping at all**. `dPgetCleanParam()` = htmLawed only (includes/main_functions.php:331): no SQL or JS protection, and quotes pass through.

## Patterns

1. **dosql files trust the caller.** `index.php` includes `dosql` before any module access check, and `CDpObject::store()` never checks ACL. In this group `do_company_aed`, `do_contact_aed`, `do_dept_aed`, `do_link_aed`, `do_config` (dataimport) and `do_communication_aed` perform create/update with zero permission checks, so they are reachable by every authenticated user regardless of module permissions. Deletes are protected only where the class inherits `CDpObject::delete()`/`canDelete()` (companies, contacts, dataimport, annotations); `CDepartment`, `CLink`, `CCommunication` override `delete()` without it. Fix centrally: either enforce `getPermission($m,'access')` in core before the dosql include **and** add `edit/add/delete` checks per dosql, or add an ACL check inside `CDpObject::store()`.
2. **`bind($_POST)` + non-casting `check()`/overridden `load()`/`delete()` = SQLi.** `bindHashToObject` (includes/db_connect.php:512) copies raw strings. Classes that build WHERE clauses by concatenating `$this-><pk>` (`CDepartment`, `CDataImport::deleteDataMap`) are injectable from the primary-key POST field. Rule: every `check()` must `intval()` the key.
3. **`dPgetCleanParam()` (htmLawed) is used as if it were SQL/JS sanitisation.** companies/vw_active.php (ORDER BY), links/index_table.php (LIKE), contacts/addedit.php (JS string) all rely on it. It only strips HTML tags; quotes pass through.
4. **Raw `$_GET`/`$_POST`/`$_REQUEST` straight into `addWhere()` strings** in the "dotmods"-origin modules (history, messages, communication, contacts/select_contact_company). These modules also have **no module-level permission check at all** (history/index.php, messages/index.php, communication/*, smartsearch*, contacts/select_contact_company.php), so every finding there is exploitable by any logged-in user.
5. **GET-triggered destructive actions** without CSRF or even POST: history/addedit.php `action=del`, communication/addedit_channel.php & addedit_frequency.php `..._id=` delete, messages `action=delete`. Combined with the raw SQL interpolation these are one-URL table wipes.
6. **Output escaping is inconsistent and the helpers are weak.** `$AppUI->___()`/`dPformSafe()` use ENT_COMPAT (single quote survives → every `onclick="...'...'..."` pattern is injectable: companies/vw_contacts.php, contacts/view.php), and `dPformSafe($v, DP_FORM_URI)` does **no** HTML escaping (companies/view.php, companies/vw_contacts.php). The dotmods modules (departments/view.php, contacts/index.php, links/index_table.php, messages/vw_messages.php, communication/*, smartsearch results) echo DB fields completely raw. Recommend: make `___()` use ENT_QUOTES, make `DP_FORM_URI` apply `rawurlencode`+`htmlspecialchars`, and sweep the listed views.
7. **Dead/legacy code that is still reachable:** smartsearchns (ereg functions → fatal on PHP 8, duplicate of smartsearch), communication/functions.php (`session_start()` re-entry, string `+` arithmetic TypeErrors), companies/index.php:27 (`$owner_filter_id_pre` undefined so the owner filter never persists), links/do_link_aed.php:119-121 (`$obj->file_id`, `$file_id` undefined). Removing smartsearchns and communication's broken GET-state passing removes several of the injection points above.
