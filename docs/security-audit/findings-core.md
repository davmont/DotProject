# Group CORE findings

Scope: index.php, base.php, fileviewer.php, queuescanner.php, classes/, includes/, functions/, style/, xmlrpc/, install/, db/, modules/public, modules/admin, modules/system, modules/groups.

Key framework fact (drives several HIGH items): in `index.php`, `$canAccess/$canRead/...` are computed for `$m` (lines 398-402) but the code never redirects on them. The `dosql` file is then `require`d unconditionally (lines 424-428). So every `do_*.php` write handler that does not perform its own permission check is reachable by any logged-in user against any module. The `modules/admin/do_*.php` handlers check internally; the `modules/system/**/do_*.php` handlers mostly do NOT.

## Non-findings verified safe (so reviewers don't re-flag)
- `classes/dp.class.php` CDpObject: `load()` intvals `$oid` (line 116); `delete()`/`canDelete()` intval `$oid` (lines 261,312) but then interpolate `$this->$k` which was just intval'd — safe. `delete()` calls `canDelete()` which enforces `checkModuleItem(...,'delete')` — authz present. `store()` uses `db_updateObject/db_insertObject` which `db_escape` every value — safe. `getAllowedRecords`/`setAllowedSQL` build `IN(...)` from `$allow`/`$deny` which come from the permissions table (ints), not user input — safe.
- `classes/query.class.php`: `addWhere($q,$params)` binds `$params` via ADOdb; `quote()`=`qstr`. The injection risk is only via the string argument when callers interpolate (documented above). `addInsert`/`addUpdate` parameterize values with `?`. Field names are not parameterizable (as noted in brief) but in core they are literals.
- `fileviewer.php`: `$file_id` is `(int)` (line 101); file path built from DB `file_project`/`file_real_filename` (not request) after an `getAllowedRecords` ownership check (lines 108-115) + `setAllowedSQL` — no traversal from request. `Content-disposition` filename uses DB `file_name` (stored, not reflected request) — low risk.
- `classes/ui.class.php` `login()` (718-778): username bound via `$q->quote()`, user_id is int from authenticator — safe. `checkFileName()` (251-264) blocks `. / \ ' ( ) " $ ;` so `m`/`a`/`u`/`dosql` cannot traverse or inject into include paths. `setState/getState` just array get/set — the risk is callers interpolating stored state (e.g. `$stub`, flagged above).
- `includes/session.php` `dPsessionRead/Write/Destroy`: `$id` is the PHP session id (not user-settable to arbitrary SQL in practice via the session cookie which PHP validates), interpolated into WHERE. Low risk; could be tightened by quoting.
- `includes/permissions.php` `getPermission()`: `$item_id` is `intval()`'d (line 91); the RPC-ADD block interpolates `$item_id` (now int) and trusted `$AppUI->user_id` — safe.
- `classes/permissions.class.php` `checkModule/checkModuleItem/checkModuleItemDenied/getDeniedItems/getAllowedItems`: interpolate `$op`,`$module`,`$userid`,`$item`. `$userid` defaults to `$AppUI->user_id` (trusted int). `$op`/`$module` callers in core pass literals (`'view'`,`'edit'`,`$m` which is checkFileName-filtered). `$item` in checkModuleItem is `$q->quote()`'d. Injection would require a caller passing raw request data as `$module`/`$op`/`$item` — none found in core.
- `modules/admin/do_user_aed.php`, `do_userrole_aed.php`, `do_user_transfer.php`: all perform `getPermission('admin'/'users'/$m, ...)` before writes; `do_user_transfer` casts project/user ids to int. Properly gated.
- `modules/public/chpwd.php`: `$user_id` is `(int)` (line 6); `$old_md5` is md5 output; `addWhere("user_password='$old_md5' AND user_id=$user_id")` uses int + 32-hex only — safe. But note: a user may change ANOTHER user's password only if `$AppUI->user_type == 1` (admin) — the check `$AppUI->user_type == 1 || loadResult()==user_id` means non-admins must know old password; OK.

## Patterns (systemic)
1. **index.php never enforces `$canAccess` before including the dosql handler or the module view.** Authorization is delegated entirely to each handler. `modules/admin` handlers comply; `modules/system/**` handlers (systemconfig, preference, syskeys, sysval, roles, translate_save) largely DO NOT, so they are reachable by any logged-in account. This is the single highest-leverage fix.
2. **`dPgetCleanParam` is treated as a sanitizer for all contexts.** It only runs htmLawed (HTML safe-mode). Developers use its output directly in (a) SQL `IN(...)`/`LIKE` interpolation (contact_selector, vw_active_usr `$stub`), (b) JavaScript contexts (selector, color_selector, calendar, date_format `callback`/`field`), and (c) filesystem paths (translate/translate_save `lang`/`module`). None of those are protected by htmLawed.
3. **`addWhere` string interpolation vs. the available bind API.** The `IN (...)` idiom is interpolated everywhere (CDpObject, contact_selector) rather than bound; safe only when the list is permission-derived ints. Request-derived lists are the injection points.
4. **Legacy crypto throughout core auth**: unsalted MD5 passwords (authenticator, admin.class, sendpass), `rand()`/`srand(microtime)` reset tokens, and an unverified `unserialize` in PostNuke auth.
5. **Installer trusts `mode` for its safety guard** instead of the presence of a config file, leaving the non-`install` path unprotected.

## 3 worst
1. **install/do_install_db.php** — the already-installed guard only fires for `mode=install`, so the `mode=upgrade` path lets an unauthenticated request rewrite `includes/config.php` (DB pointer + config values concatenated into PHP source) / trigger outbound DB connections. Delete-after-install is the only current mitigation.
2. **index.php routing gap → modules/system write handlers** — no `$canAccess` enforcement before the dosql include means any logged-in low-priv user can hit `do_systemconfig_aed`, `do_preference_aed`, `do_syskey/sysval_aed`, `roles/do_role_aed` + `do_perms_aed` and rewrite system config, other users' prefs, and grant themselves ACLs (privilege escalation).
3. **translate_save.php (weak/absent authz) + locales/core.php `eval`** — locale `.inc` files written from POST are `eval`'d on every page load; `addslashes` does not contain the array-literal breakout, giving an RCE path for anyone who can write a locale file.
