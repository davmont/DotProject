# Group D findings: helpdesk, ticketsmith, bugspray, mantis, eventum, tracIntegration, journal, reports, gallery2, hosting, mngdocument

Reachability notes that affect every row below (verified in core `index.php`):
- Login is enforced for everything routed through `index.php` (`$AppUI->doLogin()` exits before `$m/$a/dosql` are resolved). No file in scope is both self-contained and executable without a session on PHP 8 (see "Pre-auth candidates" below), so there is **no confirmed CRITICAL**.
- `index.php` computes `$canAccess/$canRead/...` but does **not** redirect on `!$canAccess` before running `dosql`. Therefore every `modules/<m>/<dosql>.php` that lacks its own permission check is reachable by **any logged-in user, even one with no permission on that module** (`?m=<m>&dosql=<file>` via GET or POST). This is what makes the mngdocument / hosting / eventum / ticketsmith dosql rows HIGH.
- `dPgetCleanParam()` = htmLawed only: it leaves `'` `"` `--` `;` untouched, so it provides no SQL protection and no protection in quoted HTML attributes.
- PHP 8 breaks several classes here (PHP4-style constructors on classes extending `CDpObject` -> `ArgumentCountError`; `get_magic_quotes_gpc()`/`mysql_real_escape_string()` undefined). Rows marked "latent" are real bugs that are currently masked by a fatal error earlier in the same request; they become live the moment someone "fixes" the fatal.

- `modules/mngdocument/documentview.php`: see LOW row.
- Everything else in scope either has the `DP_BASE_DIR` guard or references `$AppUI`/`dPgetParam` on its first lines and fatals when hit directly.

## Patterns
- **dosql handlers never check permissions, and core `index.php` runs `dosql` before enforcing `$canAccess`**: `mngdocument/do_file_aed.php`, `hosting/do_hosting_aed.php`, `eventum/do_link.php`, `do_eventum_aed.php`, `do_eventum_supplvl_add.php`, `ticketsmith/do_ticket_aed.php`, `reattachticket.php`, `helpdesk/do_item_aed.php`. Every one of these is callable by any authenticated account regardless of role. Fixing this centrally (redirect on `!$canAccess` before the `dosql` require) removes most of the HIGH rows' reach.
- **ticketsmith** is built on a private raw-SQL layer (`common.inc.php: do_query/query2result/...`) and interpolates every `dPgetCleanParam()` value directly; nothing is quoted except via `addslashes`/`db_escape` in two files. `common.inc.php:145 escape_string()` and `search.php` depend on `get_magic_quotes_gpc()` (fatal on PHP 8).
- **helpdesk list/selector/reports** interpolate every `$_GET` filter into `addWhere`/`addOrder` after stashing it in `$AppUI->setState()`; the `>= 0` guards are not sanitisation on PHP 8. `item_id` is never cast in any helpdesk view file.
- **No output escaping anywhere** in helpdesk, bugspray, hosting, journal, mngdocument, gallery2 views: DB strings go straight into HTML/attributes/JS.
- **Dead-but-dangerous code**: bugspray (old helpdesk clone), mantis (+ two full copies of PHPXMLRPC and a Mantis-side server), tracIntegration/xmlrpc (debugger, demo servers, test suite), ticketsmith/admin.php, eventum/evlink. All should be deleted rather than audited.
- **PHP4 constructors** (`function CHelpDeskItem()`, `CHDTaskLog()`, `CEventumContract()`, `CEventumSupportLevel()`, `CEventumConfig()`, `CFileLog()`) silently break create/edit paths on PHP 8 and currently mask several SQLi/eval sinks; the sinks must be fixed before the constructors are.
- Files written into the web root: mngdocument `SGD/` (user uploads, any name), helpdesk `configure.php` (PHP config with unescaped values), eventum `configure.php` (`dp_config.php` into an arbitrary directory).
