## Patterns

1. **Unvalidated ORDER BY everywhere.** `earnings/index.php`, `invoices/index.php`, `payments/index.php`, `registers/vw_registers.php`, `registers/vw_mngdocument_logs.php` and all five `opportunities/vw_idx_details*.php` take `orderby`/`order_by`/`order` from `$_GET` and pass it straight into `addOrder()` or a raw `ORDER BY`. Several persist the value in `$AppUI->setState()`, so one poisoned request keeps injecting on every subsequent page load. Only `risks/index_table.php` does it right (`in_array($_GET['orderbyy'], $valid_ordering)`).
2. **Dosql files with zero permission checks.** `costs/do_costs_aed.php`, `costs/do_budget_aed.php`, `costs/do_budget_reserve_aed.php`, `risks/do_risks_aed.php`, `opportunities/do_opportunities_aed.php`, `invoices/do_invoice_aed.php`, `invoices/do_updateproduct.php`, `payments/do_payment_aed.php`, `registers/do_updateregisters.php` all do `bind($_POST)` -> `store()`/`delete()` with no `getPermission`/`getDenyEdit` and no ownership/project check. The addedit views check, but the dosql is directly callable, so the checks are decorative. The only module in scope that does it properly is `inventory/do_inventory_aed.php` (`checkModuleItem` for view/edit/delete). None of these deletes are GET-friendly (`del` is read from `$_POST`).
3. **Session-state filters as SQL.** `inventory` (f1/f2/f3/quick_filter), `earnings`/`invoices`/`payments` (orderby) store raw request values in `$AppUI->setState()` and later interpolate them into SQL. `getState()` must be treated as tainted.
4. **finances.class.php builds all WHERE clauses by string concatenation** of ids/years that come straight from `dPgetParam()` with no casting (`loadProjects`, `loadTasks`, `loadMPTasks`, `haveRangedChildren`, `getAllChildrenIds`). `export_excel.php` exposes the same functions over GET with no permission check.
5. **earnings module is pre-DBQuery legacy code**: every write is hand-built SQL with `$_POST` concatenation; also uses `split()`/`mysql_free_result()` (fatal on PHP 8 in some branches) and `<? echo` short tags, so parts are broken and parts leak source.
6. **No output escaping in any list/view in scope** (costs, earnings, inventory, invoices, opportunities six "6V" columns, registers, risks). Combined with pattern 2, any low-privilege user can store script that renders for approvers/admins.
7. `makeFileNameSafe()` (core, used by `invoices/reports.php`) is a single-pass `../` strip and is bypassable with `....//`; any other caller of it in the codebase has the same traversal.
8. Dead/broken modules: `unitcost` (undefined `setItem()`, unused `$pre_save` hook), `modules/install` (no code). `earnings` partially broken on PHP 8.
